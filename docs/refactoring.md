## 기능 확장

| 후보 | 내용 | 걸리는 것 |
|---|---|---|
| NULL과 추가 타입 | 인코딩에 null 비트맵, 비교·출력은 3값 논리 | 저장 포맷 version 2 |
| WHERE 확장 | `AND`/`OR`, `<` `>` `BETWEEN`. 범위 조건은 B+tree 리프 순회 | 실행기를 연산자 트리로 바꿈 (§7.3) |
| LIMIT과 키셋 페이지네이션 | `WHERE id > x LIMIT n`을 B+tree 범위 탐색으로 | 범위 질의 |
| compaction | UPDATE·DELETE(#20)로 쌓인 옛 버전·묘비를 걷어 낸 새 파일을 만들고 rename. 지운 최대 id를 헤더나 표시 레코드로 남겨야 nextId가 줄지 않음 | 포맷(최대 id 기록), 교체 중 읽는 쪽 fd |
| 여러 프레임에 걸친 쓰기 배치 | 지금은 한 요청의 변경분이 프레임 하나(4 MiB) 안이어야 함. 커밋 표시 레코드로 여러 프레임을 하나로 묶음 | 포맷 변경, 복구 규칙 |
| `SET col = col + 1` 같은 식 | 지금 SET은 리터럴만 | 식 평가기 |
| 스냅샷 스캔 | 스캔 중 커밋된 다행 UPDATE·DELETE가 일부만 보이는 문제(#21). 레코드에 이전 버전 위치를 두거나 MVCC | 포맷 변경 |
| 보조 인덱스 | id 외 컬럼 인덱스, 중복 키 | 트리의 유일 키 가정 |
| SELECT를 포함한 배치 | 배치 안 SELECT가 커밋 전의 같은 배치 행을 봄 (read-your-writes) | 배치 실행 모델 |
| 여러 테이블 배치 | 테이블별 락 순서 고정 | 교착 회피 |

## 성능

| 후보 | 내용 |
|---|---|
| 맨 오른쪽 특수 분할 | 순차 삽입 시 리프 충전율 50% → ~100%. 반반 분할과 충전율 비교 |
| group commit | 여러 요청의 프레임을 모아 fsync 한 번으로 |
| prepared statement | 한 번 파싱한 쿼리를 값만 바꿔 재실행 |
| 인덱스 스냅샷 | 체크포인트 오프셋 기록 → 원자적 교체 → 나머지 보충. 재스캔은 대비책으로 남김 |

## 인터페이스

| 후보 | 내용 |
|---|---|
| REST → AST 매핑 | SQL 문자열을 거치지 않고 AST로 바로 번역 (SQL 인젝션 방지, 파싱 한 번) |
| HTTP와 JSON 직접 파싱 | cpp-httplib 대체 |
| 요청 단위 디스패치 (이벤트 루프) | 지금은 keep-alive 연결 하나가 워커 하나를 붙잡는다 (architecture §19). epoll로 연결을 받고 완성된 요청만 워커에 넘기면 워커 수와 연결 수가 분리된다 |
| CLI 출력 폭을 글자 기준으로 | 지금은 바이트 기준이라 한글 정렬이 어긋남 |
